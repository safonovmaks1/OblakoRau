# OblakoRau 2.0 — Data Model

**Статус:** проект спецификации
**Версия:** 1.0
**Назначение:** единая модель данных для самостоятельного интернет-магазина с возможностью подключения внешних CMS и backend.

---

## 1. Принятые решения

| Параметр                            | Решение                                |
| ----------------------------------- | -------------------------------------- |
| Варианты товаров                    | Размеры, цвета и другие характеристики |
| Валюты                              | Мультивалютность                       |
| Учёт остатков                       | Включён                                |
| Заказ без регистрации               | Запрещён                               |
| Будущие интеграции                  | WooCommerce, OpenCart, 1С-Битрикс      |
| Источник данных на этапе разработки | JSON Mock API                          |
| Основная модель                     | Независимая от CMS                     |

## 2. Общие принципы

1. У каждой сущности есть собственный уникальный идентификатор.
2. Товары и варианты товаров — разные сущности.
3. Цена хранится отдельно от отображаемого форматирования.
4. Остатки учитываются на уровне варианта товара, если товар имеет варианты.
5. Корзина хранит ссылки на товар и вариант, а не копии всего товара.
6. Заказ содержит неизменяемый снимок названий, цен, вариантов и количества на момент оформления.
7. Внешние CMS не должны диктовать внутреннюю структуру приложения.
8. Все цены, скидки и доступность при создании заказа повторно проверяются на сервере.
9. Идентификаторы внешних CMS хранятся отдельно от внутренних ID.

## 3. Основные сущности

### 3.1 Product — товар

```json
{
	"id": "prod_001",
	"slug": "chanel-classic-flap",
	"sku": "CH-78512",
	"name": "Chanel Classic Flap",
	"brandId": "brand_chanel",
	"categoryIds": ["cat_bags"],
	"description": "Описание товара",
	"shortDescription": "Краткое описание",
	"images": [],
	"attributes": {},
	"variantIds": ["var_001", "var_002"],
	"hasVariants": true,
	"status": "published",
	"isFeatured": false,
	"createdAt": "2026-11-16T12:00:00Z",
	"updatedAt": "2026-11-16T12:00:00Z"
}
```

Обязательные поля:

- `id`
- `slug`
- `name`
- `status`

Дополнительные правила:

- `sku` может быть общим артикулом модели.
- Если товар имеет варианты, индивидуальный SKU задаётся каждому варианту.
- `images` содержит ссылки на изображения и их назначение.
- `attributes` содержит характеристики, общие для всех вариантов.
- `status`: `draft`, `published`, `archived`.

### 3.2 ProductVariant — вариант товара

Каждый размер, цвет или комбинация характеристик — отдельный вариант.

```json
{
	"id": "var_001",
	"productId": "prod_001",
	"sku": "CH-78512-BLK-M",
	"barcode": null,
	"attributes": {
		"size": "M",
		"color": "black"
	},
	"priceId": "price_001",
	"stock": {
		"quantity": 5,
		"reserved": 0,
		"available": 5,
		"trackInventory": true,
		"allowBackorder": false
	},
	"status": "active"
}
```

Правила:

- Вариант принадлежит одному товару.
- SKU варианта уникален в пределах каталога.
- Остатки учитываются по варианту.
- `available` вычисляется как `quantity - reserved`; это производное значение, его нельзя считать независимым источником истины.
- Если `trackInventory` включён, нельзя оформить заказ сверх доступного остатка, если отдельно не разрешён backorder.
- Если товар не имеет вариантов, система всё равно должна иметь однозначный способ связать его с ценой и остатком. Рекомендуется использовать один технический вариант.

### 3.3 ProductAttribute — характеристики

Характеристики должны быть расширяемыми, а не зашитыми в код.

Примеры:

- размер;
- цвет;
- материал;
- тип одежды;
- размер обуви;
- объём;
- производитель;
- сезон.

Структура определения характеристики:

```json
{
	"id": "attr_color",
	"name": "Цвет",
	"code": "color",
	"type": "select",
	"isVariantAttribute": true,
	"options": [
		{
			"value": "black",
			"label": "Чёрный"
		},
		{
			"value": "white",
			"label": "Белый"
		}
	]
}
```

Типы:

- `text`
- `number`
- `boolean`
- `select`
- `multiselect`

Характеристика может использоваться в фильтрах каталога, карточке товара и комбинациях вариантов.

### 3.4 Price — цена

Мультивалютность должна поддерживаться на уровне модели.

```json
{
	"id": "price_001",
	"variantId": "var_001",
	"amounts": {
		"RUB": 4200000,
		"USD": 45000,
		"EUR": 41000
	},
	"compareAtAmounts": {
		"RUB": 4800000,
		"USD": 51000,
		"EUR": 47000
	},
	"isActive": true
}
```

Все суммы хранятся в минимальных денежных единицах валюты:

- RUB: копейки;
- USD: центы;
- EUR: центы.

Нельзя хранить деньги в виде чисел с плавающей точкой или строк с символами валют.

Правила:

- Валюта всегда задаётся ISO 4217.
- Валюта отображения выбирается отдельно от базовой валюты каталога.
- Конвертация не должна происходить автоматически без утверждённого курса и правил округления.
- Источник курса валют — отдельный сервис.
- Для заказа фиксируются цена и валюта на момент оформления.
- Если для выбранной валюты нет цены, система применяет явно настроенную стратегию: конвертация по курсу или отсутствие продажи в этой валюте. Молчаливое переключение валюты запрещено.

### 3.5 Category — категория

```json
{
	"id": "cat_bags",
	"parentId": null,
	"name": "Сумки",
	"slug": "bags",
	"description": "Описание категории",
	"image": "/assets/images/categories/bags.webp",
	"sortOrder": 10,
	"status": "active"
}
```

Поддерживается иерархия категорий через `parentId`.

### 3.6 Brand — бренд

```json
{
	"id": "brand_chanel",
	"name": "CHANEL",
	"slug": "chanel",
	"logo": "/assets/images/brands/chanel.svg",
	"description": ""
}
```

### 3.7 Customer — покупатель

Регистрация обязательна до оформления заказа.

```json
{
	"id": "customer_001",
	"email": "customer@example.com",
	"phone": "+79990000000",
	"firstName": "Имя",
	"lastName": "Фамилия",
	"passwordHash": "managed-by-auth-service",
	"status": "active",
	"createdAt": "2026-11-16T12:00:00Z"
}
```

Важно:

- Пароль никогда не хранится в открытом виде.
- В реальном приложении хеширование и проверка пароля выполняются backend/auth-сервисом.
- Frontend не должен самостоятельно создавать или проверять хеши паролей.
- Email должен быть уникальным в рамках системы.

### 3.8 CustomerAddress — адрес покупателя

```json
{
	"id": "addr_001",
	"customerId": "customer_001",
	"type": "shipping",
	"country": "RU",
	"region": "Ленинградская область",
	"city": "Санкт-Петербург",
	"street": "Примерная улица",
	"house": "10",
	"apartment": "25",
	"postalCode": "190000",
	"isDefault": true
}
```

Адреса доставки и платёжные адреса должны быть отделены логически.

### 3.9 Cart — корзина

```json
{
	"id": "cart_001",
	"customerId": "customer_001",
	"currency": "RUB",
	"items": [
		{
			"productId": "prod_001",
			"variantId": "var_001",
			"quantity": 2
		}
	],
	"updatedAt": "2026-11-16T12:00:00Z"
}
```

Правила:

- Корзина принадлежит авторизованному покупателю.
- Идентичность позиции определяется комбинацией `productId + variantId`.
- Повторное добавление того же варианта увеличивает количество.
- Количество должно быть положительным целым числом.
- Цена и наличие при отображении корзины актуализируются через каталог.
- Локальное хранение может использоваться как временный кэш, но не является авторитетным источником данных.
- При входе в аккаунт локальная корзина может быть объединена с серверной по согласованным правилам.

### 3.10 Order — заказ

```json
{
	"id": "order_001",
	"number": "OR-2026-000001",
	"customerId": "customer_001",
	"status": "pending_payment",
	"currency": "RUB",
	"items": [
		{
			"productId": "prod_001",
			"variantId": "var_001",
			"sku": "CH-78512-BLK-M",
			"name": "Chanel Classic Flap",
			"variantName": "Чёрный, M",
			"unitPrice": 4200000,
			"quantity": 2,
			"lineTotal": 8400000
		}
	],
	"totals": {
		"subtotal": 8400000,
		"discount": 0,
		"shipping": 50000,
		"tax": 0,
		"total": 8450000
	},
	"shippingAddress": {},
	"billingAddress": {},
	"deliveryMethod": "courier",
	"paymentMethod": "card",
	"paymentStatus": "unpaid",
	"createdAt": "2026-11-16T12:00:00Z"
}
```

Заказ содержит снимок данных на момент создания. Изменение товара или цены в каталоге не должно менять уже оформленный заказ.

Статусы заказа:

- `draft`
- `pending_payment`
- `paid`
- `processing`
- `shipped`
- `completed`
- `cancelled`
- `refunded`

Статусы оплаты:

- `unpaid`
- `pending`
- `paid`
- `failed`
- `refunded`
- `partially_refunded`

### 3.11 Inventory — остатки

Остатки относятся к вариантам товаров.

Для будущей поддержки нескольких складов рекомендуется отдельная сущность складских остатков:

```json
{
	"id": "inventory_001",
	"variantId": "var_001",
	"locationId": "warehouse_main",
	"quantity": 5,
	"reserved": 1,
	"updatedAt": "2026-11-16T12:00:00Z"
}
```

Правила:

- Остаток не может быть отрицательным.
- Резервирование должно выполняться атомарно на backend.
- При создании заказа проверяется актуальное наличие.
- Отмена заказа освобождает резерв.
- Подтверждённая продажа уменьшает физический остаток согласно правилам backend.
- В будущем допускается несколько складов и распределение остатков.

### 3.12 Favorite — избранное

```json
{
	"customerId": "customer_001",
	"productIds": ["prod_001", "prod_002"],
	"updatedAt": "2026-11-16T12:00:00Z"
}
```

Избранное хранится в аккаунте покупателя. Локальный кэш допустим для быстрого отображения.

### 3.13 Review — отзыв

```json
{
	"id": "review_001",
	"productId": "prod_001",
	"customerId": "customer_001",
	"rating": 5,
	"title": "Отличный товар",
	"text": "Текст отзыва",
	"images": [],
	"status": "pending",
	"createdAt": "2026-11-16T12:00:00Z"
}
```

Статусы:

- `pending`
- `approved`
- `rejected`

Возможность оставлять отзывы только после покупки может быть включена настройкой магазина.

## 4. Связи сущностей

```text
Brand
  └── Product

Category
  └── Product

Product
  ├── ProductVariant
  │     ├── Price
  │     └── Inventory
  ├── ProductAttribute
  ├── Review
  └── Favorite

Customer
  ├── CustomerAddress
  ├── Cart
  ├── Order
  ├── Favorite
  └── Review

Cart
  └── CartItem
        ├── Product
        └── ProductVariant

Order
  └── OrderItem
        ├── Product reference
        └── Variant reference
```

## 5. Правила оформления заказа

1. Покупатель должен быть авторизован.
2. Корзина должна содержать хотя бы одну позицию.
3. Проверяется существование товаров и вариантов.
4. Проверяется статус публикации товара.
5. Повторно проверяются цены и валюта.
6. Проверяются остатки и доступное количество.
7. Проверяется доступность выбранного способа доставки.
8. Пересчитываются скидки, доставка, налоги и итоговая сумма.
9. Создаётся заказ со снимком данных.
10. Выполняется резервирование остатков.
11. Запускается процесс оплаты.
12. После подтверждения оплаты обновляется статус заказа.

Все критические операции выполняются backend. Frontend не может самостоятельно подтверждать оплату или списывать остатки.

## 6. Идентификаторы внешних систем

Внутренние ID не должны зависеть от ID WooCommerce, OpenCart или Битрикс.

Рекомендуется отдельная таблица соответствий:

```json
{
	"id": "external_001",
	"entityType": "product",
	"internalId": "prod_001",
	"provider": "woocommerce",
	"externalId": "1542",
	"externalUpdatedAt": null
}
```

Поддерживаемые провайдеры:

- `woocommerce`
- `opencart`
- `bitrix`
- `custom`

Для одного внутреннего объекта допускается несколько внешних соответствий.

## 7. Что входит в первую реализацию

Первая версия модели должна поддерживать:

- товары и категории;
- бренды;
- варианты товаров;
- характеристики;
- несколько валют;
- цены;
- учёт остатков;
- аккаунты покупателей;
- адреса;
- корзину;
- избранное;
- оформление и хранение заказов.

Отзывы, промокоды, бонусы, несколько складов, подарочные сертификаты и сложные правила скидок проектируются как расширения, а не обязательная часть первого этапа.

## 8. Важное архитектурное ограничение

JSON Mock API имитирует получение данных, но не является полноценным backend.

Реальные аккаунты, авторизация, оплата, атомарное резервирование остатков, создание заказов и защита персональных данных требуют серверной реализации.

Эта модель является внутренним контрактом приложения. Каждый CMS-адаптер обязан преобразовывать данные внешней системы в этот контракт и обратно.
